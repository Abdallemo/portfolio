### The Origin Story
I built this tool during my internship to automate the tedious process of keeping the frontend and backend in sync. I was tired of manually typing endpoint strings and worrying about typos in path parameters. I thought, *"Why not let the Go compiler tell the frontend what's available?"*

### The Problem vs. Solution
**The Problem**: The gap between Go backends and TypeScript frontends often leads to runtime errors due to mismatched routes, missing path parameters, or inconsistent data types. Standard solutions like tRPC often require switching to a specific framework, which isn't always feasible.

**The Solution**: A lightweight ecosystem that bridges this gap. By scraping your Go source code (AST), `go-route-gen` creates a unified map of all your routes, which the `@abdallemo/routegen-client` then consumes to provide 100% type safety.

### Deep Tech Specs
- **CLI (The AST Scraper)**: Written in Go, it uses the standard `go/ast` and `go/parser` packages to crawl your project for `net/http` route patterns. It specifically looks for `METHOD /path` signatures and extracts path parameters (e.g., `{id}`).
- **Frontend Client**: A strictly-typed Axios wrapper that takes the generated JSON and turns it into a set of TypeScript generics.

### The "Clever" Logic: AST Scraping
The core logic involves identifying where routes are defined. Instead of using regex (which is brittle), I used Go's abstract syntax tree to find specific function calls that define routes.

```go
// Simplified AST Scraping logic
func (v *Visitor) Visit(node ast.Node) ast.Visitor {
    call, ok := node.(*ast.CallExpr)
    if !ok { return v }

    sel, ok := call.Fun.(*ast.SelectorExpr)
    if !ok { return v }

    // Check if the method is "HandleFunc" or "Handle"
    if sel.Sel.Name == "HandleFunc" || sel.Sel.Name == "Handle" {
        if len(call.Args) > 0 {
            if lit, ok := call.Args[0].(*ast.BasicLit); ok {
                // We found a route string like "GET /users/{id}"
                v.Routes = append(v.Routes, lit.Value)
            }
        }
    }
    return v
}
```

### Installation

```bash
# Go CLI
go install github.com/Abdallemo/go-route-gen@latest

# Frontend Client
npm install @abdallemo/routegen-client
```

### Quick Start: Type-Safe Requests

```typescript
import { GoApiClient } from '@abdallemo/routegen-client'
import { API_ROUTES } from './route' // Generated by Go CLI

export const api = new GoApiClient<typeof API_ROUTES>({
  baseURL: 'http://localhost:8080'
})

// TS requires the 'id' parameter because it's in the Go route!
await api.expect<User>().request('GET /users/{id}', { id: 101 })
```

### Lessons Learned
I originally tried to use regex for the scraper, but it failed on complex Go formatting. Switching to the `ast` package was a turning point. It's more complex to implement, but it's 100% accurate because it uses the same logic as the Go compiler itself.
